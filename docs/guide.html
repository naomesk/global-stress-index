Team guide

You own the disasters and pandemic module and you combine everyone's work. This page takes you from an empty folder to a published report. Every command runs from the project folder.

Real data first. The code was tested on synthetic stub data only; the numbers in the report came from an earlier run on real downloads. Before you trust any result, run on real data and check that it matches the report (section 2).

1. Set up the base

Install Python 3.11 or newer and Git, then open a terminal in the folder where you keep projects.

Create the repository. On GitHub choose New repository, name it global-stress-index, keep it public (free GitHub Pages needs that), and add no files. Then unzip the code base into a folder of the same name and push it:

cd global-stress-index
git init -b main
git add .
git commit -m "Add code base"
git remote add origin https://github.com/YOUR-USER/global-stress-index.git
git push -u origin main

The .gitignore keeps raw downloads, virtual environments and zip files out of the repository.

Make a virtual environment and install the packages.

python -m venv .venv
source .venv/bin/activate          # Windows: .venv\Scripts\activate
pip install -r requirements.txt

Run the tests. They build their own stub data in a temporary folder, so they never touch your files. All should pass.

python -m pytest -q

Try the whole pipeline on stub data. Every figure carries a STUB watermark so nobody mistakes it for a finding.

python make_stub_data.py
python run_all.py
python make_stub_data.py --clean     # remove stub files before using real data

Share it with the team. Add Naomi and Noé under Settings, Collaborators. Each person works on a branch and opens a pull request into main:

git checkout -b climate-module
# ...work...
git add data/processed outputs/climate
git commit -m "Climate module on real data"
git push -u origin climate-module

Processed files and each member's outputs/ folder are small, so committing them is fine; raw downloads are not committed.

Send teammates the setup message: clone the repo, make the environment, run the tests, then run your own module. Send me data/processed/<domain>.csv, <domain>_meta.json and your outputs/ folder.

python -m modules.disasters_pandemics

If a file is missing, the error says which one and where to save it. When it finishes you have:

Check it against the report

  • The cleaning log shows how many values were filled or flagged. Know these numbers; a reader may ask.
  • Disaster deaths per million are very skewed. After log(1 + x) the skewness should drop from about 3.2 to about 1.0.
  • The pandemic score should sit flat until 2019 and peak in 2021 near 4.6.
  • The mortality score should fall from about 3.2 in 1959–1960; the climate score should rise from about −1.9 to +1.9.

Small differences are normal if a source was revised. A big one (a pandemic peak in the wrong year, a skew that stays high) means a wrong column or unit. Check it before moving on.

Check the hand-off file

python -m common.contract data/processed/disasters.csv
python -m common.contract data/processed/pandemic.csv

It prints OK or every problem it finds.

3. Bring in teammates' modules

The finished module may not follow the hand-off format. tools/adopt.py checks what you were sent and converts it. It never edits their file: it keeps a copy in data/submissions/<domain>/ and writes every decision to outputs/adopted/<domain>/ADOPTION_REPORT.md. Put each file in a folder outside data/processed first (for example incoming/).

See where you stand.

python -m tools.adopt status

It lists each domain as OK, MISSING or INVALID, and warns if some domains were built from stub data and others from real data.

Look at the file you received.

python -m tools.adopt inspect incoming/their_file.csv

It finds the year column, lists missing years, and shows each column's range, skew and trend. It then suggests a convert command.

Pick the case that matches and run it. Then run status again.

A. They followed the format (a .csv and a _meta.json) 
python -m tools.adopt install --domain climate --file incoming/climate.csv --meta incoming/climate_meta.json

It copies both files into data/processed/ and validates them. If validation fails the message lists every problem; fix it with case B on their raw columns, or ask them to rerun.

B. They sent cleaned indicators, but not in the format

Typical: a column called Year, a gap or two, other column names, no standardizing. Decide for each column whether higher means more stress. If lower means more stress (life expectancy, sea ice), pass it to --flip.

python -m tools.adopt convert --domain climate --file incoming/climate_raw.csv \
    --indicators temp_anomaly,co2_ppm,sea_ice --flip sea_ice --pca

Useful options:

OptionUse it when
--flip a,bLower values of these columns mean more stress
--pcaWeight the indicators with the first principal component (the climate method in the report)
--weights a=2,b=1You want unequal weights
--aux aKeep a column but leave it out of the score (weight 0), like birth rate
--log1p aThe column is a very skewed count
--zero-fill aA missing year means “nothing recorded”
--max-edge-fill NThe file starts late or ends early by a few years (default 1; more is refused)
--projection a=minChoose the 2100 rule: trend, trend_scaled or min

Defaults: climate indicators use trend_scaled, pandemic uses min, everything else trend. A column named score or ending in _z is renamed with a submitted_ prefix so it cannot clash with the format.

C. They only sent a finished score 
python -m tools.adopt convert --domain pandemic --file incoming/pandemic.csv --score-only burden

The score is standardized and used as it is. The report will say the module's internals are theirs; ask them for a sentence describing how they built it.

With a single score the 2100 scenarios can only extend its trend, so the result is less informative than with raw indicators. Ask for the indicators if you can.
D. They only have a notebook or nothing yet

Ask them to save one table: a year column and the indicators they used, as .csv or .xlsx. In a notebook that is df.to_csv("file.csv", index=False). Then use case B. If they have nothing, they can run the shared module for their domain on the real downloads (python -m modules.climate or modules.demographics); that is the fallback.

E. Monthly or daily data, or a different year range

Several rows in one year need a rule for combining them:

python -m tools.adopt convert --domain mortality --file incoming/monthly.csv --agg mean

Use mean for rates and levels, sum for counts. Dates in any common format are read; the tool takes the year. If the file does not cover 1959–2024 it stops and tells you; it never invents years beyond the edge-fill limit. Excel files work too (--sheet NAME).

Read the adoption report and the warnings

After each conversion read the printed CHECK lines and ADOPTION_REPORT.md. The tool warns when:

  • a climate indicator falls over time (the sign may be wrong);
  • a column is very skewed (skew above 2);
  • the pandemic score peaks outside 2020–2023;
  • a PCA loading is not positive, meaning one indicator moves against the others.

Every flip, fill and weight must go into the Methodology of the report so that it describes what was actually done.

4. Combine

python -m tools.adopt status       # all four domains OK, none mixed with stub data
python combine.py

combine.py stops with a clear message if a domain is missing, invalid, or built from stub data while others are real. On success it writes outputs/combined/:

index.csv, periods.csv, kmeans_selection.csv, label_spreading_confusion.csv, scenarios.csv, scenario_summary.csv, test_errors.csv, rf_importance.csv, results_summary.json and figures 1–5.

Open results_summary.json first. If "data_is_stub" is true, none of it is a finding.

Edit the Word file: replace the figures, the tables and every number in the text that changed. Search for the old numbers (for example “2021”, “88%”) to be sure none is left.

Each member writes their own results paragraph from their outputs/<module>/ tables. Keep the writing in one voice when you merge.

Rebuild the web page from the Word file (needs pandoc):

python -m tools.build_report_page path/to/End_of_the_World_Report.docx

That rewrites docs/report.html, docs/figures/ and the downloadable Word file. The home page's findings table is typed by hand in docs/index.html; update it to match.

Open docs/index.html in a browser and read the report page once, including the equations and the tables.

6. Publish on GitHub Pages

Commit and push the docs/ folder to main.

git add docs
git commit -m "Update report page"
git push

On GitHub open Settings, Pages. Under Build and deployment choose Deploy from a branch, branch main, folder /docs, and Save.

Wait a minute or two. The site is at https://YOUR-USER.github.io/global-stress-index/. Put that link in the course submission.

The docs/.nojekyll file tells GitHub to serve the files as they are. All links in the site are relative, so it works under the repository's sub-path.

Troubleshooting

You seeDo this
MissingRawFile naming a fileDownload it and save it at the path in the message (section 2).
ModuleNotFoundErrorActivate the virtual environment, then pip install -r requirements.txt.
Python cannot find common or toolsRun from the project folder, with python -m ....
“Mixed data” from combine.pySome modules ran on stub data. Run python make_stub_data.py --clean, rerun those modules on real downloads.
“Several rows share one year”Add --agg mean (or sum for counts).
“Cannot continue” on short coverageAsk for 1959–2024 data, use --zero-fill if missing means nothing recorded, or allow edge years with --max-edge-fill.
Pandemic score peaks in the wrong yearWrong column or units. Compare with the report: the peak is 2021.
Site shows a 404Pages must be set to main, /docs; index.html must sit directly in docs/; the repo must be public on a free plan.
Equations look brokenThe page uses MathML, which current Chrome, Edge, Firefox and Safari draw. Update an old browser.
